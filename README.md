# 🛵 拼单算路 · 双平台接单计算器

给 Uber Eats / DoorDash 跑单用的手机小工具：手上有一单时，又弹出一个新单，**几秒钟判断这单要不要一起接**。

## 它算什么
输入两单的取餐/送达地址和金额，它用真实路线算出：

- 只送手上这单（A）：多少 km、多少分钟
- 接上新单一起送（最优取送顺序）：多少 km、多少分钟
- **额外多跑**：多少 km、多少分钟
- 新单**每公里赚多少**（分别按「平台显示距离」和「实际多跑的公里」）
- 一个结论：✅ 接 / ⚠️ 顺路才接 / ❌ 不接

## 怎么装到 iPhone 上（1 分钟）

它是一个纯网页，**需要 HTTPS 才能用 GPS 定位**。最省事的免费托管：

### 方式一：Netlify Drop（最快，不用注册）
1. 电脑浏览器打开 https://app.netlify.com/drop
2. 把整个 `courier-stack-calc` 文件夹拖进去
3. 得到一个 `https://xxxx.netlify.app` 网址
4. 用手机 Safari 打开这个网址 → 点底部「分享」按钮 → 「添加到主屏幕」
5. 桌面上就有图标了，以后当 App 用

### 方式二：GitHub Pages
1. 新建仓库，把 `index.html` 传上去
2. Settings → Pages → 选 main 分支 → 保存
3. 得到 `https://你的用户名.github.io/仓库名/` 网址，同上加到主屏幕

## 怎么用
1. 设置「每公里目标」（默认 $2/km）和「新单时段加价」（DoorDash 每单 +$1/$2 填这里）
2. 手上这单（A）：填取餐/送达地址、金额（勾选「已取到餐」可跳过取餐点）
3. 新弹出来的单（B）：填取餐/送达地址、金额、平台距离
4. 点「📍 定位」用 GPS 填当前位置（影响绕路判断，很重要）
5. 点「计算」看结果

地址填得越具体越准（带街道名 + 区），比如 `McDonald's, 185 Elizabeth St, Melbourne VIC 3000`。

## 注意 / 限制
- 路线用免费 **OSRM** 演示服务（目前按 🚗 驾车算）；电动车/步行先按驾车近似，距离误差通常很小。
- 地理编码用免费 **Photon**（OpenStreetMap）。
- 数据只在你手机本地算，不上传。
- 免费接口偶尔会限流，工具内置了自动重试。

## 📷 截图识别（新）
在「新弹出来的单（B）」里点 **📷 选截图识别**，上传新单的截图：

- 自动识别**金额 / 距离 / 时长**并填进表单（英里会自动换成公里）
- 尝试识别**取餐店名**（会在地址框里标「识别，请核对」）
- 立刻给一个**快速单价判定**：这单 $/km 达不达标

> 说明：
> - 首次使用要联网下载识别引擎（约 3MB），之后有缓存；识别在手机本地跑，截图不上传。
> - **送达地址**两家平台接单前通常不显示，所以截图识别主要帮你做「金额 ÷ 距离」的快速过滤；要算「合并 vs 单跑」的精确路线，仍需手动补送达地址（如果看得到的话）。
